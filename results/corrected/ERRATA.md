# Errata to the frozen configuration and campaign notes

Found by the final audit of 21 September 2026. The frozen configuration is left as committed; this file records where it, or our notes, describe the runs incorrectly. None of these changes a reported number.

1. **Reward subsample seed.** `frozen_config.json` says the reward-loop subsample is drawn by the training seed. It is not. `scripts/train_taskaware_grpo.py` does not pass `--seed` to `make_grpo_reward`, whose default is `seed=42`, so all fifteen policies (and the submitted ones) were scored on the same 48/24 UNSW-NB15 subsample. The per-source clean reference MCC is identical in all fifteen reward logs (0.4966, 0.5674, 0.7303, 0.8284). The five training seeds therefore vary initialization and sampling, not the reward data. Overlap of that subsample with the evaluation splits is 0 to 3 of 72 records, none in a training partition (`reward_eval_overlap.json`, key `reward_seed42`).
2. **Eq. 9 random draw.** The frozen configuration says the base point of the perturbation test uses the training seed. The code uses a fixed seed for every run. No effect on results.
3. **Substituted circuits.** Eight of the 45 circuits in `circuits/` are the source circuit substituted by the emission script because greedy decoding was invalid: all three members of `corr_lr10_s42` and `corr_lr10_s43` (collapsed runs; last valid sampled completion at about steps 51 and 182) and the Z member of `corr_lr75_s42` and `corr_lr75_s46`. `structure.json` reports `all_valid: true` because it validates the substituted file.
4. **Interrupted runs.** After the power failure of 15 September 2026, `corr_lr5_s44` resumed from checkpoint-25 and `corr_lr5_s45` and `corr_lr5_s46` restarted from step zero. The reward logs hold 30,112 lines, of which 112 belong to the interrupted first attempts.
5. **Rescoring files.** `rescoring_*.json` score every committee on five subsamples (seeds 42 to 46). Only the `"42"` block is the subsample the policies were trained on; the article quotes that block.
6. **Provenance.** Result files do not store a git commit, and `job_records.jsonl` begins after the power failure. No scientific source file changed between commit `07c2ab7` and the end of the campaign. Training logs and model checkpoints are not in this repository.
7. **Verifier coverage.** `scripts/verify_paper_numbers.py` checks the cells of the main result tables (549 values). It does not check in-text numbers, the values of the two downstream compression tables (split counts only), or the C sweep table.
